How it works

Three steps, and no template to click together

You describe the fields in words. There is no sample to upload, no region to draw and no positional rule that breaks when a sender changes their layout.

  1. Describe the fields

    A name, one of 13 types and a sentence of description per field — string, date, currency, enum, typed arrays of objects and more. Change it over the API at any time.

    { "name": "total", "type": "currency",
  "description": "grand total incl. tax" }

  2. Send the mail

    Forward it to your mailbox’s own address on @smooth-operator.online, post raw MIME to /v1/parse, or drop the MailMint node after n8n’s IMAP or Gmail trigger.

    k7m2xq4h9bwz@smooth-operator.online
invoices.k7m2xq4h9bwz@…   # slug alias
k7m2xq4h9bwz+acme@…       # +tag survives

  3. Get JSON you can check

    A signed webhook, a polling feed or the n8n trigger. Route on one boolean: needs_review is true whenever any field is doubtful, missing or unsupported by the text.

    x-mailmint-signature: t=1787648043,v1=6a1f…
{ "id": "msg_01JQ8Z…", "needs_review": false,
  "fields": { … } }

Confidence & evidence

When it gets something wrong, it says so

“How do I find out that it went wrong?” is the question the n8n, Make and Zapier threads keep asking. Every value MailMint returns carries four keys — value, confidence, source and evidence — so the answer is in the payload.

  • Computed, never taken from the model. A model will report 0.95 on a value it invented, so its self-report may only ever lower a score. The ceiling comes from signals that can be checked.
  • The evidence check runs. If the quoted span is not really in the message, the score is capped at 0.3 and the field is flagged hallucinated_evidence:<field>.
  • Two extractors, independently. Deterministic rules and the model both run. Agreement earns "source": "rule+llm"; disagreement keeps the rule’s value, lowers the score and raises rule_llm_disagreement:<field>.
  • The arithmetic has to reconcile. Line items against the subtotal, subtotal + tax + shipping − discount against the total. Failing sets arithmetic_mismatch.
  • Missing is null. Never invented, never “N/A”, never a default you chose. A required field that is absent raises missing_required:<field>. The full rule.

What else is in the box

The unglamorous half, done properly

“We have an LLM” is not a product. The value is the part nobody wants to write: real MIME turned into clean text, tables that keep every row, and an honest answer about who sent it.

Forty rows in, forty rows out

Declare "type": "array" of objects and get a real nested array. Rows are found three ways — HTML grid, repeating DOM blocks, aligned text — and reconciled. row_count and truncated ride on every table; 1, 40 and 520-row tables come out complete.

Re-parse mail you already received

The original RFC822 bytes are kept, so a schema fix can be dry-run over last month’s real mail ("dry_run": true) and then applied. Re-delivery is a separate switch, so tuning never fires a month of webhooks at you. Every result carries parse.schema_version.

Attachments you can address

Each file is its own object with inline and content_id — the pair that separates the invoice PDF from the signature logo. GET /v1/attachments/:id serves the bytes. 25 MB inbound, 10 MB per stored attachment.

SPF, DKIM and DMARC, for real

Evaluated against live DNS, not copied from someone else’s header. A forward that broke the body hash is dkim: "body_altered", not fail. Where a result genuinely cannot be computed it says none instead of a pass we did not earn.

Clean text, reply chain removed

Quoted-printable decoded, legacy charsets normalised to UTF-8, RFC 2047 and 2231 resolved. You get the raw text, the HTML, text rendered from HTML, and body.stripped_text with the quoted thread and signature taken off.

Signed webhooks that retry

hmac_sha256(secret, t + "." + rawBody) with the timestamp inside the signature. Six attempts at 0 s, 30 s, 2 m, 10 m, 1 h and 6 h, a stable delivery id for idempotency, and several endpoints per mailbox, each with its own secret.

Built, not yet wired up — said plainly

MailMint does not read text out of a PDF attachment yet. The extractor exists (packages/docs: PDF text and tables, spreadsheets, DOCX, OCR fallback) and the response has the slot for it, attachments[].extracted, but nothing populates that slot today. A message whose data lives only inside the PDF gives you the file, its metadata and its checksum, not its contents.

The API

One request to try it. No address, no DNS.

POST /v1/parse takes raw MIME — or just a subject and a body — plus your schema, and returns the same object a mailbox would deliver. Nothing is stored.

  • Bearer key, JSON in, JSON out. Machine-readable reference at /openapi.json (OpenAPI 3.1).
  • Mailboxes when you are ready. Create one, get an address, set a webhook_url or read the /v1/events feed.
  • Filter on doubt. GET /v1/messages?needs_review=true is a review queue with no extra code.

# Stateless. No address, no DNS, nothing stored.
curl -X POST $MAILMINT_URL/v1/parse \
  -H "Authorization: Bearer $MAILMINT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
  "subject": "Invoice INV-2291 from Acme Ltd",
  "text": "Invoice INV-2291\n\nTotal: $31.50\nDue: Sep 8, 2026\n",
  "schema": [
    { "name": "invoice_number", "type": "string",
      "description": "the invoice or reference number" },
    { "name": "total", "type": "number",
      "description": "grand total including tax" },
    { "name": "due_date", "type": "date",
      "description": "when payment is due" }
  ]
}'
import { readFile } from 'node:fs/promises';

const raw = await readFile('message.eml');
const res = await fetch(`${process.env.MAILMINT_URL}/v1/parse`, {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${process.env.MAILMINT_API_KEY}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    raw_mime: raw.toString('base64'),
    schema: [
      { name: 'invoice_number', type: 'string' },
      { name: 'total',          type: 'number' },
    ],
  }),
});
const result = await res.json();
if (result.needs_review) console.warn('check this one:', result.flags);
console.log(result.fields.total.value, result.fields.total.confidence);

raw = pathlib.Path("message.eml").read_bytes()

res.raise_for_status()
result = res.json()

total = result["fields"]["total"]

Questions

Before you wire anything up

Do I need an inbound address to try it?

No. POST /v1/parse takes raw MIME, or just a subject, text and html, plus your schema — and stores nothing at all. It is the same parser, the same response shape, and the same confidence numbers. The quickstart starts there.

Where does the confidence number come from?

Not from the model. It is computed from signals we can verify: whether the quoted evidence is really a verbatim substring of the message; whether the deterministic rules layer and the model independently agreed; whether the invoice arithmetic reconciles; and whether the value coerced cleanly to its declared type. The model’s own self-report is one input with the smallest weight, and it may only lower a score. The full rule is in the docs.

What happens to a message that fails to parse?

It is still delivered. A message with any flag on it arrives at your webhook with needs_review: true and the flags naming what went wrong and in which field. Nothing is ever silently dropped, and a field that could not be found is null — never invented, never a placeholder string.

Can I verify that a webhook really came from MailMint?

Yes. Every delivery carries x-mailmint-signature: t=<unix>,v1=<hex>, where the hex is hmac_sha256(secret, t + "." + rawBody). The timestamp is inside the signed string, so a captured request cannot be replayed. There are worked verification examples in Node and Python — copy one, do not guess.

Is any of this live?

Yes. The API is live at mailmint.app.mintapis.com; the hosted inbound address works — mail sent to your @smooth-operator.online address is received, authenticated and parsed; the n8n node is on npm and in n8n’s verified registry; and paid plans are live through Stripe. What does not exist yet: a published uptime history, an SLA, a SOC 2 report, or a customer logo or testimonial we have permission to quote. See the status page.

What about prompt injection from a hostile email?

It is a real risk in any product that pipes attacker-controlled email into a model, and we will not pretend it is solved. What exists is a structural mitigation, not a control: a value is only accepted with a high confidence when its evidence is a verbatim substring of the message, when the deterministic layer independently agrees, or when the arithmetic reconciles — none of which an instruction embedded in a body can manufacture. Treat parsed output as data, and check needs_review before acting on it.
